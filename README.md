# History Video · 中文历史解说视频 Skill

供支持本地 Skill 的 AI 工具使用的历史视频制作技能。从查史料、写解说稿，到画面方案、配音、字幕、本地预览和成片导出，按阶段完成。可在 Windows、macOS、Linux 上按所需阶段配置环境。

文风只有一个目标：**用大白话把事情讲清楚，十岁孩子也能听懂。** 不哄孩子、不念论文，也不靠连续的“怎么办呢”“你看”装口语。

## 能做什么

- 写历史人物、朝代、战役与历史事件的完整解说稿，附标题、开场候选和史料记录。
- 以真实地图组织逐镜讲解，叠加人物、建筑、军队、道具等插图或史料图像；不生成场景背景。
- 调用豆包 TTS 配音，生成时间轴、混音和经过中文强制对齐的字幕。
- 制作 30 秒试片与完整本地预览，确认后导出 MP4、SRT 和封面。
- 从已有工程继续，按指定段落或时间段修改。

可以只用它写稿，不必做完整视频。它是供智能体执行的技能和脚本集合，完整制作还需要相应工具、素材和服务凭据。

## 安装

先将仓库克隆到本地：

```sh
git clone https://github.com/asen5269/history-video-skill.git history-video
```

将完整的 `history-video` 文件夹放入所用 AI 工具支持的技能目录，或按该工具的方式加载 [SKILL.md](SKILL.md)。也可以直接下载仓库。不同工具的技能目录、调用语法和工具权限可能不同，以各自配置为准。

以 Codex 默认个人技能目录为例：Windows 为 `%USERPROFILE%\.codex\skills\history-video`，macOS / Linux 为 `~/.codex/skills/history-video`。其他工具请使用其支持的技能目录。如果目标目录已存在，先检查自己的修改，不要直接覆盖。

写稿需要资料检索和文件读写能力；完整视频制作还需要运行本地脚本、访问相关服务和预览页面的能力。具体工具未提供这些能力时，只能完成其支持的阶段。

## 怎么用

直接给主题、工作目录和当前要做的阶段。下面使用自然语言调用；支持专用 Skill 调用语法的工具，也可以通过技能选择器或相应语法调用：

```text
使用 history-video，在 projects/朱元璋 写一篇朱元璋解说稿。
用大白话讲故事，十岁孩子也能听懂，先只写稿。
```

继续已有工程：

```text
使用 history-video，继续 projects/朱元璋。
文稿已确认，开始做画面方案。
```

局部修改：

```text
使用 history-video，修改 projects/朱元璋 的解说稿。
鄱阳湖这一段讲得更清楚，删掉重复总结。
```

## 文稿怎么写

先讲谁遇到了什么事、做了什么、接着发生什么。官职和制度影响理解时，结合当时的事情解释一句。

用日常说话的词，长短句自然交替，按完整意思分段。不会把每段都写成“提问—回答—总结”，也不要求每段都有笑点或金句。配音数据需要拆句，但技术上的拆句不决定正文的句长和段落。

史实与评论分开。重要事件保留出处与原文定位；找不到依据的对白、动作和人物心理不编。史书中的指控也不直接当成已经独立证实的事实。

详细要求见[研究规范与口播验收](references/research.md#解说文风)。

## 制作流程

默认视觉为“地图讲解＋插图辅助”：全片以地图为背景，围绕地点、路线与势力变化推进。家族关系等内容可在地图上叠加关系图；地图不能全程只是模糊的装饰底图。插图按叙事需要出现，不遮挡正在讲解的地名、路线和边界。历史位置、路线和疆域都需有依据，局部家谱与地图须标明省略范围。

| 阶段 | 主要成果 | 确认事项 |
| --- | --- | --- |
| 查资料、写稿 | 正文、3–5 个标题、3 个开场候选、来源记录、预计时长 | 正文与开场；最终标题另行选定 |
| 画面方案 | 分镜、美术设定、3 张代表性静帧、3 秒运动样片 | 方案 |
| 30 秒试片 | 真实配音、画面、字幕、音乐与音效 | 试片 |
| 完整预览 | 可播放、暂停、拖动的本地页面 | 审阅、修改 |
| 导出 | MP4 与 SRT | 明确确认导出 |
| 封面 | 3:4 与 4:3 两种封面 | 成片和最终标题已确认 |

默认面向抖音、视频号，单条目标时长 10–20 分钟，画幅为 1920×1080、30 fps。内容自然决定长度，不靠停顿凑时长。来源留在工程文件里，默认不放进成片画面和结尾。

确认记录保存在 `project.json`。通过试片不代表授权导出；修改已有工程时，从当前阶段继续。

## 环境与凭据

只写稿时，不需要配音或生图服务凭据。进入相关制作阶段后再准备：

| 用途 | 依赖 |
| --- | --- |
| 制作脚本 | Node.js、Python |
| 音频处理和媒体校验 | FFmpeg、ffprobe |
| 豆包配音 | 系统 curl、可用的豆包 TTS 应用与音色权限 |
| 中文字幕强制对齐 | WhisperX 及所需模型，首次运行需下载 |
| AI 辅助插图（可选） | 需要生成独立插图时，按生图接口规范配置服务；不生成背景 |
| 画面合成与预览 | 相应的 HyperFrames 或 Remotion 环境 |

在项目目录或其上级工作目录创建 `.env` 或 `key.env`，填写对应配置：

```dotenv
DOUBAO_TTS_APPID=你的应用ID
DOUBAO_TTS_TOKEN=你的访问令牌
HV_IMAGE_BASE_URL=你的生图服务地址
HV_IMAGE_API_KEY=你的生图服务密钥
```

凭据不要放进 Skill 目录或提交到 GitHub。配音接口、认证格式和音色配置以[配音规范](references/voice.md)为准；生图配置见[生图接口](references/imagegen.md)。

在 Skill 目录下运行环境检查，将示例路径换成实际工程目录。下列命令可直接在终端执行，无需额外的 PowerShell 启动命令：

```sh
node scripts/doctor.mjs "projects/朱元璋"
```

检查只报告凭据是否存在。缺少某项工具或凭据时，只暂停依赖它的步骤。

## 工程文件

| 文件 | 内容 |
| --- | --- |
| `project.json` | 主题、阶段、规格、确认记录 |
| `script.json` | 逐句文案、配音文本、标题、开场与证据 |

完整格式见[工程数据](references/project.md)。

## 检查与限制

文稿完成后，在仓库目录运行结构检查：

```sh
node scripts/gate.mjs "projects/朱元璋" --stage script
```

结构检查能核对字段、证据记录及相应阶段的数据一致性，不能证明史实正确、口播自然或画面好看。这些仍需人工复核。

字幕对齐真实配音，不按字数平均分配时间。地图需要与故事年代匹配；缺少历史边界时，使用地形与地点，不拿别的年代疆域代替。网络图片与音乐还需核对来源和使用许可。
